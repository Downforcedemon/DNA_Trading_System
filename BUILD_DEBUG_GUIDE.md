# DNA Trading System - Build Debugging Guide

## Overview
This document details all build issues encountered and their solutions for the IBKR TWS API integration.

---

## Issue 1: Protobuf Version Mismatch

### Error Messages
```
error: This file was generated by an older version of protoc which is incompatible with your Protocol Buffer headers
error: 'AuxillaryParseTableField' in namespace 'google::protobuf::internal' does not name a type
error: 'struct google::protobuf::internal::ArenaStringPtr' has no member named 'UnsafeArenaRelease'
```

### Root Cause
- Generated `.pb.cc` and `.pb.h` files were created with `protoc 3.12.4`
- System protobuf library was version `3.19.6`
- **C++ requires exact version match** between generated code and runtime library

### Diagnosis Commands
```bash
# Check system protobuf library version
pkg-config --modversion protobuf

# Check protoc compiler version  
protoc --version

# Check version in generated file (look for line with version number)
head -20 external/ibkr/protobufUnix/Contract.pb.h | grep -E "3012|3019"
```

### Solution
Regenerate protobuf files using the system's protoc version.

**Step 1: Download TWS API with proto source files**
```bash
wget https://interactivebrokers.github.io/downloads/twsapi_macunix.1042.01.zip -O twsapi_latest.zip
unzip twsapi_latest.zip -d twsapi_latest
```

**Step 2: Regenerate protobuf C++ files**
```bash
cd twsapi_latest/IBJts/source
protoc --proto_path=./proto \
       --experimental_allow_proto3_optional \
       --cpp_out=/path/to/project/external/ibkr/protobufUnix \
       proto/*.proto
```

### Key Takeaways
- Always match `protoc` version with `libprotobuf` version
- The `--experimental_allow_proto3_optional` flag is needed for proto3 optional fields
- IBKR provides `.proto` source files in `IBJts/source/proto/`

## Issue 2: Missing Intel Decimal Floating-Point Library

### Error Messages
```
undefined reference to `__bid64_from_string'
undefined reference to `__bid64_to_string'
```

### Root Cause
IBKR's `Decimal.cpp` uses Intel's Binary Integer Decimal (BID) library for precise decimal arithmetic. This library is not included in standard Linux repos.

### Diagnosis
```bash
# Check if libbid exists on system
ldconfig -p | grep -i bid
find /usr -name "*libbid*" 2>/dev/null

# Check what symbols are needed
nm external/ibkr/Decimal.cpp.o | grep bid64
```

### Solution
Build Intel Decimal Floating-Point Library from source.

**Step 1: Download**
```bash
wget http://www.netlib.org/misc/intel/IntelRDFPMathLib20U2.tar.gz
tar -xzf IntelRDFPMathLib20U2.tar.gz
```

**Step 2: Fix compatibility issues (modern GCC)**
```bash
cd IntelRDFPMathLib20U2/LIBRARY
# Add missing includes
sed -i '32i #include <stdlib.h>' src/bid64_pow.c
sed -i '31i #include <stdlib.h>' src/bid128_pow.c
```

**Step 3: Build**
```bash
make CC=gcc CALL_BY_REF=0 GLOBAL_RND=0 GLOBAL_FLAGS=0 UNCHANGED_BINARY_FLAGS=0 CFLAGS="-w"
rm *.o
cp libbid.a /path/to/project/external/
```

**Step 4: Update CMakeLists.txt**
```cmake
# Add to target_link_libraries
target_link_libraries(dna_system pthread ${Protobuf_LIBRARIES} 
    ${PROJECT_SOURCE_DIR}/external/libbid.a)
```

### Key Takeaways
- IBKR API depends on Intel BID library for decimal precision
- Library must be built from source on Linux
- Use `CFLAGS="-w"` to suppress warnings in legacy code

## Issue 3: Missing dfp Library

### Error
Initial attempt to link with `dfp` failed because `libdfp` doesn't contain Intel BID symbols.

### Diagnosis
```bash
nm -D /usr/lib64/libdfp.so | grep bid64  # Returns nothing
```

### Solution
Use Intel's `libbid.a` instead of system `libdfp`.

## Useful Commands Reference

### CMake/Make
```bash
# Clean rebuild
cd build && rm -rf * && cmake .. && make

# Verbose make output
make VERBOSE=1

# Parallel build
make -j$(nproc)
```

### Protobuf
```bash
# Generate C++ from proto
protoc --proto_path=./proto --cpp_out=./output proto/*.proto

# Check protobuf versions
pkg-config --modversion protobuf
protoc --version
```

### Library Debugging
```bash
# Find undefined symbols
nm -u myobject.o

# Check library symbols
nm -D /path/to/library.so | grep symbol_name

# Find which package provides a file
dnf provides '*/filename'

# Check library dependencies
ldd executable
```

### Package Management (Fedora)
```bash
# Install development package
sudo dnf install -y package-devel

# Search packages
dnf search keyword

# Find what provides a library
dnf provides '*libname*'
```

## CMakeLists.txt Final Configuration
```cmake
cmake_minimum_required(VERSION 4.2.1)
project(DNA_Trading_System VERSION 1.0)
set(CMAKE_CXX_STANDARD 23)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

include_directories(${PROJECT_SOURCE_DIR}/include)
include_directories(${PROJECT_SOURCE_DIR}/external)
include_directories(${PROJECT_SOURCE_DIR}/external/ibkr)
include_directories(${PROJECT_SOURCE_DIR}/external/ibkr/protobufUnix)

file(GLOB_RECURSE SOURCES "src/*.cpp")
file(GLOB IBKR_SOURCES "${PROJECT_SOURCE_DIR}/external/ibkr/*.cpp")
file(GLOB IBKR_PROTOBUF_SOURCES "${PROJECT_SOURCE_DIR}/external/ibkr/protobufUnix/*.cc")

add_executable(dna_system ${SOURCES} ${IBKR_SOURCES} ${IBKR_PROTOBUF_SOURCES})

find_package(Protobuf REQUIRED)

target_link_libraries(dna_system 
    pthread 
    ${Protobuf_LIBRARIES} 
    ${PROJECT_SOURCE_DIR}/external/libbid.a)
```
